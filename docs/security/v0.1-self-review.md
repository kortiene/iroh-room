# v0.1 GA Internal Structured Security Self-Review

- **Status:** **In progress.** Nothing in this document is a result yet; each
  row records what must be checked and where its evidence will be linked.
- **Decision:** [`ADR-0014`](../decisions/ADR-0014-v0.1-ga-sdk-cli-small-rooms-scope.md)
  OD-2, decided 2026-11-15; roadmap amendment RB-1.3 in
  [`ROADMAP.md`](../../ROADMAP.md).
- **Owner:** Maintainer (release owner).
- **Scope:** the v0.1 GA candidate: the `iroh-rooms` SDK (stable tier and the
  `experimental` tier), its closure (`iroh-rooms-core`, `iroh-rooms-crypto`,
  `iroh-rooms-net`), and the `iroh-rooms` CLI, in the shipped configuration
  (full mesh, 5-member cap, `gossip_overlay` off, plaintext content per OD-1).

## What this is, and what it is not

This is **not** an independent security review. v0.1 GA ships with
WAIVER-PBETA-0003 ("no independent security review completed") accepted for
v0.1 GA only and disclosed in [`SECURITY.md`](../../SECURITY.md). The
independent review (`RB-SEC-010` #344, `RB-FC-009` #353) is `POST-GA` and is
required before v0.2 or any public beta expansion.

This document is the evidence record the RB-1.3 gate exception relies on. The
gate item is satisfied only when every checklist item below is complete with
linked evidence, at the exact candidate commit.

## 2. Reachability inventory (tied to `RB-REL-007` #343)

- [ ] Inventory every CLI command and every stable-tier SDK export, with the
      test that exercises it.
- [ ] List every capability the README, SECURITY.md, guides, and release notes
      advertise, and map each to a reachable surface or remove the claim.
- [ ] **Encryption-claims entry (OD-1):** confirm no CLI, SDK, or doc surface
      implies content confidentiality beyond transport encryption to admitted
      peers; confirm `SyncConfig::encrypted_content_writes` is never set by
      production code and the rotation builder is only in
      `iroh_rooms::experimental::rotation`.
- [ ] Confirm `gossip_overlay` / `large_rooms` are off in every shipped
      artifact.
- [ ] **Member removal (RB-1.4, #379):** confirm `room remove` (admin-only,
      `insufficient_role` otherwise) and `room leave` are reachable and tested
      (`crates/iroh-rooms-cli/tests/member_cli.rs`, the ignored online
      `two_peer_e2e.rs` removal/leave tests, and
      `crates/iroh-rooms-net/tests/manager_e2e.rs`), and that every surface
      describing removal uses the honest wording: removed members lose access to new messages, files and pipes once peers see the removal; they keep what they already had.
- [ ] Link the inventory from #343.

## 4. Fuzzing: CBOR and frame parsers

The existing evidence is property tests
(`crates/iroh-rooms-core/tests/cbor_property.rs`) and malformed-input tests;
there is no coverage-guided fuzz harness yet.

- [ ] Add a `cargo-fuzz` target for the untrusted-input decoders:
      `WireEvent::decode` (`crates/iroh-rooms-core/src/event/wire.rs`),
      `SignedEvent::decode` (`event/signed.rs`), `SyncMessage::decode`
      (`sync/message.rs`), and `RoomInviteTicket::from_str` (`ticket.rs`).
- [ ] Frame layer: `read_frame` (`crates/iroh-rooms-net/src/frame.rs`) is async
      over an iroh stream; factor out or wrap a pure length-prefix decode so it
      can be fuzzed, or document why the length cap makes it out of scope.
- [ ] Run each target for an agreed minimum time; record the duration, corpus,
      and any crash, with fixes and regression tests.
